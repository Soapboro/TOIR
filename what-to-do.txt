Система должна поддерживать и выполнять следующие функции:
– регистрация и авторизация пользователей с разграничением прав доступа по ролям;
– ведение карточек оборудования (учётные данные, технические характеристики, паспортная информация);
– регистрация заявок на ремонт с указанием описания неисправности, приоритета и ответственного исполнителя;
– автоматическая генерация и рассылка уведомлений ответственным сотрудникам (по e-mail и/или в интерфейсе системы) о необходимости проведения ТО или ремонта;
– хранение полной истории технического обслуживания и ремонтов каждой единицы оборудования;
– прогнозирование вероятных неисправностей на основе анализа исторических данных о поломках и периодичности ремонтов;
– формирование и ведение планов-графиков планового технического обслуживания с учётом наработки и регламентов;
– формирование аналитических отчётов по показателям надёжности оборудования и выполнению плана ТОиР.
2.3 Входная и выходная информация
Входной информацией системы являются: паспортные данные оборудования (наименование, модель, серийный номер, год выпуска, место установки); данные о выполненных работах по техническому обслуживанию и ремонту (вид работы, дата, исполнитель, описание выполненных работ); сведения о неисправностях и заявках на ремонт; регламенты технического обслуживания (виды ТО, периодичность, перечень работ); данные о сотрудниках и их ролях в системе.
Выходной информацией системы являются: уведомления ответственным сотрудникам о необходимости проведения обслуживания или ремонта; прогнозы вероятных неисправностей с указанием единицы оборудования и ожидаемых сроков; планы-графики планового технического обслуживания; аналитические отчёты по выполнению плана ТОиР; история обслуживания по каждой единице оборудования.
2.4 Эксплуатационные требования
Система должна функционировать в режиме веб-приложения, доступного через браузер. Для работы с системой пользователю необходимы: персональный компьютер, планшет или смартфон; браузер с поддержкой JavaScript (Google Chrome, Mozilla Firefox, Microsoft Edge актуальных версий); подключение к корпоративной сети или сети интернет. Система должна быть доступна круглосуточно (режим 24/7) с допустимым временем планового простоя не более 2 часов в месяц. 
2.5 Требования к безопасности
Пароли пользователей должны храниться в базе данных исключительно в виде хэша с применением алгоритма bcrypt. Аутентификация должна реализовываться на основе JWT-токенов с ограниченным сроком действия. Каждая роль пользователя должна иметь строго определённый набор прав доступа к функциям системы – пользователь одной роли не должен иметь возможности воспользоваться функциями, предназначенными для другой роли. Все запросы к API должны передаваться по защищённому протоколу HTTPS.
2.6 Требования к инструментам разработки
Серверная часть системы должна быть реализована на языке Python (версия 3.9 и выше) с использованием фреймворка FastAPI [15]. Для работы с базой данных применяется ORM SQLAlchemy. Клиентская часть системы должна быть разработана с использованием библиотеки React. В качестве СУБД используется PostgreSQL (версия 13 и выше). Для отправки уведомлений применяется SMTP-протокол. Тестирование API производится с помощью инструмента Postman.
2.7 Требования к техническим средствам
Для функционирования системы необходимо два сервера: сервер для back-end приложения и сервер для базы данных. Рекомендуется предусмотреть резервирование сервера базы данных для обеспечения отказоустойчивости.
Требования к серверу back-end приложения: операционная система Ubuntu 22.04 LTS; процессор с тактовой частотой не менее 2,5 ГГц, 4 ядра и более; оперативная память не менее 8 ГБ; SSD-накопитель объёмом не менее 128 ГБ.
Требования к серверу базы данных: операционная система Ubuntu 22.04 LTS; процессор с тактовой частотой не менее 2,5 ГГц, 4 ядра и более; оперативная память не менее 8 ГБ; SSD-накопитель объёмом не менее 256 ГБ.
Требования к рабочей станции пользователя: оперативная память не менее 4 ГБ; браузер с поддержкой JavaScript; подключение к корпоративной сети.
2.8 Требования к графическому интерфейсу
Графический интерфейс системы должен быть выполнен в едином стиле на всех страницах. Интерфейс должен быть адаптивным для корректного отображения на экранах различных размеров (настольный компьютер, планшет). Шрифт должен поддерживать кириллицу. Интерфейс должен быть интуитивно понятным для сотрудников с различным уровнем компьютерной грамотности. Цветовое оформление должно соответствовать корпоративной символике предприятия. Уведомления и статусные сообщения должны быть хорошо различимы и содержать исчерпывающую информацию для пользователя.
